# RCQR-01 demo software
Turning Technologies QT "clicker" (RCQR-01) hardware and software exploration (WIP).
My adventures in reverse engineering an interesting platform.

<img src="docs/rcqr01-04.jpg" width="400" />

## hardware
* based on nrf51822 (QFAA, 16kB ram, 256kB flash, Cortex M0)
* low ram (non 32k model) makes it very tricky to run any BLE softdevice.

### Display
 * lcd 340x160 (viewable), 2-bit grayscale
 * ST7586 chipset connected to serial bus. Use SPI to transfer data to chip.
 * custom u8g2/u8x8 driver for the ST7586
 * unusual pixel column format (packed 3 pixels per byte)
 * one-page u8g2 tile buffer, 360 bytes (45 tiles x 8), to keep RAM usage low
 * Microchip MCP1256 3.3v boost converter/regulator powers lcd stuff
 
### eeprom
 * CAT25512 512-Kb SPI Serial CMOS EEPROM
 
### keyboard
 * 8x8 matrix, qwerty style. Glow-in-the-dark keypad is a neat touch.
 * rows have external pullups?

## software
* build system is VS Code + [PlatformIO](https://platformio.org/)
* target environment is `nrf51_rcqr01_standalone`
* use an external nRF5 SDK 12.3.0 checkout at `../nRF5_SDK_12.3.0_d7731ad`
* prepare and verify the SDK once:
  ```sh
  python3 scripts/setup_sdk.py
  ```
  Set `NRF_SDK_DIR` in `.env` or pass `--sdk /path/to/sdk` if it is elsewhere.
* build with:
  ```sh
  python3 -m platformio run -e nrf51_rcqr01_standalone
  ```
* use ST-Link (or J-Link) for flashing/debugging; see [Debugging](#debugging) below
* display rendering uses [u8g2](https://github.com/olikraus/u8g2) with a project-specific ST7586 u8x8 driver

### Debugging

Debugging goes through an ST-Link over SWD (SWDIO/SWDCLK on the
battery-compartment test pads). PlatformIO drives OpenOCD, and both
`NRF_LOG_*` output and direct `SEGGER_RTT_*` calls land on RTT channel 0.

#### session setup

`platformio.ini` configures the `nrf51_rcqr01_standalone` environment with
`debug_tool = stlink` plus two settings that shape every debug session:

* `debug_init_break = tbreak src/main.c:<line>` — halt at a line inside
  `main()` after `SEGGER_RTT_Init()`. Breaking at `main()` itself is too
  early: the RTT control block does not exist yet and `monitor rtt setup`
  reports "No control block found". **If `main.c` gains or loses lines,
  update the line number so the break still lands after `SEGGER_RTT_Init()`
  and before `NRF_LOG_INIT()`.**
* `debug_extra_cmds` — sources `scripts/start-rtt.gdb` and runs its
  `start-rtt` command at the init breakpoint. It tells OpenOCD where the RTT
  control block lives (`monitor rtt setup 0x20000000 0x4000 "SEGGER RTT"`),
  starts RTT, and publishes it as a TCP server on `localhost:9090`.

From VS Code, pick a `PIO Debug` launch configuration in the Run and Debug
view: `PIO Debug` rebuilds and flashes before attaching, while
`PIO Debug (skip upload)` reuses the firmware already on the chip. The launch
configurations in `.vscode/` are generated by PlatformIO and contain
machine-local absolute paths — regenerate them with PlatformIO's "Debug"
command instead of editing them by hand.

The same session is available from the terminal:

```sh
python3 -m platformio debug -e nrf51_rcqr01_standalone
```

Flash without a debug session:

```sh
python3 -m platformio run -e nrf51_rcqr01_standalone -t upload
```

#### reading the log

With the target halted at the init breakpoint, connect any TCP client to the
RTT server, then continue the session (`F5` / `continue`):

```sh
nc localhost 9090
```

Expected startup trace: `entered main`, `startup: log initialized`,
`startup: timers initialized`, `startup: graphics initialized`,
`startup: display drawn`, ..., `startup: entering main loop`
(full checklist in `docs/plans/u8g2-migration.md`).

#### gotchas

* Attach a log viewer before trusting the log: the nRF5 SDK serial backend
  writes to RTT non-blocking and silently **drops messages** once the buffer
  fills with no reader attached.
* Do not add GDB's `silent` command to the breakpoint command list in
  `platformio.ini`. In MI mode GDB then emits a bare `*stopped` record, which
  the PlatformIO debug adapter cannot parse; the adapter exits, VS Code drops
  the session, and orphaned GDB/OpenOCD processes keep the target halted.
  Run `scripts/cleanup-orphaned-gdb.zsh` to find and stop such orphans.

### Graphics

The display is initialized by `display_init()` in `src/display.c`. The custom
`src/u8x8_d_st7586_rcqr01.c` driver handles the panel geometry: the viewable
area is 340x160, while the u8x8 model pads the width to 360 (45 tiles) to
match the controller's three-pixels-per-byte layout and to skip the hidden
controller columns. Rendering uses u8g2 page mode with a one-page 360-byte
buffer (45 tiles x 8 bytes, ~6.8 KB less RAM than a full framebuffer). The
application uses `u8g2_font_7x13_tf` for small text and
`u8g2_font_10x20_tf` for larger text.

The Nordic SDK sources required by PlatformIO are selected in
`src/sdk_includes.c` and compiled directly from the external SDK checkout.
The PlatformIO pre-build script validates the SDK path and configures all
include and linker paths from the same root.

## SDK patches

The project uses nRF5 SDK 12.3.0. `scripts/setup_sdk.py` applies and verifies
the three compatibility fixes needed by this project:

1. Fix the ESB channel getter name in `components/proprietary_rf/esb/nrf_esb.h`
2. Use `SWI3` for the app timer handler in `components/libraries/timer/app_timer.c`
3. Read the ESB address bytes bytewise in `components/proprietary_rf/esb/nrf_esb.c`.
   `m_esb_addr` has byte alignment, so the SDK's 32-bit load can become an
   unaligned access; the Cortex-M0 then hard-faults during `radio_init()`.

The SDK root defaults to:

```text
../nRF5_SDK_12.3.0_d7731ad
```

Set `NRF_SDK_DIR` in `.env`, or pass `--sdk` to the setup script, to use a
different checkout. The historical patches remain under `patches/` as
documentation of the required changes; the setup script applies the equivalent
edits idempotently.
